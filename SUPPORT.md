# Getting Help with FluxV2X

Thank you for using FluxV2X! We welcome inquiries, defect reports, and feature proposals from users and contributors worldwide.

To ensure your request is handled effectively and routed to the proper channels, please review the guidelines below.

---

## 1. Questions, Configuration, and Community Discussions
- **Usage & Deployment Questions**: If you are unsure how to configure environment variables, deploy via Docker, or set up a dataset schema mapping, please consult:
  - [Documentation Overview](docs/product/PRODUCT_OVERVIEW.md)
  - [Deployment Guide](docs/operations/DEPLOYMENT.md)
  - [Troubleshooting Guide](docs/operations/TROUBLESHOOTING.md)
- **GitHub Discussions**: Open a thread in [GitHub Discussions](https://github.com/Pranay-Kumar-02/flux-v2x/discussions) to ask questions or discuss architecture with other users.

---

## 2. Reporting Software Defects (Bugs)
If you have discovered a bug in the application, data processing engine, or frontend:
1. Verify that your local branch or deployment is up to date with `main`.
2. Search [existing GitHub Issues](https://github.com/Pranay-Kumar-02/flux-v2x/issues) to verify the defect has not already been reported or resolved.
3. Open a new issue using our [Bug Report Template](.github/ISSUE_TEMPLATE/bug_report.yml).
4. Provide:
   - Operating system and environment details (Docker, local Python version, Node.js version).
   - Minimal reproduction dataset or steps.
   - Relevant log snippets (ensuring all secrets, passwords, and sensitive IPs have been scrubbed).
   - Expected versus observed outcome.

---

## 3. Requesting Features and Enhancements
We welcome architectural proposals, new ML model integrations, spatiotemporal clustering algorithms, and offline mitigation policies:
1. Review the [Project Roadmap](docs/product/ROADMAP.md) to see if the feature is already planned.
2. Submit a proposal using the [Feature Request Template](.github/ISSUE_TEMPLATE/feature_request.yml).
3. Outline the motivation, target persona, mathematical or security specification, and backward compatibility considerations.

---

## 4. Reporting Security Vulnerabilities
**Do not report suspected security vulnerabilities, secret leaks, or authentication flaws in public GitHub issues.**

Please refer to our [Security Policy](SECURITY.md) for confidential disclosure instructions:
- Use [GitHub Private Vulnerability Reporting](https://github.com/Pranay-Kumar-02/flux-v2x/security/advisories/new) if available.
- Alternatively, email encrypted details to [security@fluxv2x.org](mailto:security@fluxv2x.org).

---

## 5. Scope of Support
FluxV2X is an open-source software project distributed under the Apache-2.0 License. Support is provided on a best-effort basis by community contributors. There are no commercial service-level agreements (SLAs) or guaranteed 24/7 turnaround times.
